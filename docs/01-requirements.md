# 01 需求规格 · 合璧字幕 HebiSubs

> 文档版本：v0.3（草案，P3 定稿）｜ 建立：2026-10-15 ｜ v0.2：2026-10-16 C11 P1 复盘修订（F1.4、F2.1、F4.2、F4.3、F5.1–F5.3、F6.8、F8.2、开放问题 6–7）｜ v0.3：2026-10-16 C12 P2 复盘修订（F1.4、F3.2、F3.4、F4.2、F4.4、F5.1、F5.2、F5.4、F6.6、F6.7、F8.2、非功能「限额」、开放问题 3–5）
> 标记：✅ 已确认 ｜ 🔶 草案待确认 ｜ ❓ 开放问题
> P2 实测依据：`docs/api-notes/subhd.md`、`assrt.md`、`archive-tools.md`、`jellyfin-subtitle-naming.md`

## 1. 背景

- MP（V3）+ Jellyfin 观影；外国电影需要中英（简中+外语）双语字幕。
- 资源常只带中字或只带英字，手动找字幕、放进媒体文件夹很麻烦。
- 平时主要在 SubHD 找字幕（中英特效字幕丰富）。
- 试用海拉鲁字幕大师发现：SubHD 结果**不按下载量排序**、**不显示制作组**、难分好坏；**整包压缩包无法处理**。

## 2. 功能需求

### F1 触发方式
- ✅ F1.1 新资源整理入库后自动处理（MP 整理完成事件）
- ✅ F1.2 扫描历史媒体库，为缺字幕影片补全（分批、限速、可暂停）
- 🔶 F1.3 手动对单部影片触发搜索，并可人工挑选候选
- 🔶 F1.4 跳过条件 =「已满足落盘目标」：同目录已有 ≥2 份合格的简中+外语双语外挂字幕（华语片见 F6.8）；只有简中单语或繁体时**继续处理**；语言判定通过样本测试之前，判不准的一律视为「不满足」（宁可多找，不漏）（P1 复盘：海拉鲁「已有任意中文就跳过」会漏）
  - 「已有字幕」按 **Jellyfin 的识别规则**判定：只看视频同目录、文件名（去扩展名）以「视频名（去扩展名）+ `.`」开头、扩展名在 Jellyfin 字幕名单里的文件；**子目录里的不算**（包括 `Subs/`，Jellyfin 不读）。（P2-D）
  - 语言不看文件名后缀（`chs` / `cht` / `chi&eng` 在 Jellyfin 里是「未定义」，文件名标记本身也不可信），以正文判定（F5.2）为准；我们自己写的文件以状态记录（F8.1）和存档索引（F6.7）为准

### F2 影片识别
- 🔶 F2.1 身份来源分入口：**自动触发**以整理完成事件的 `mediainfo` 为主（已带 TMDB ID；事件发出时 NFO 可能尚未刮削生成，待 P5 实测）；**历史库扫描**读 MP 生成的 `movie.nfo`；两者统一成同一个任务输入。IMDb ID、原名、中文名、年份都纳入身份；**豆瓣 ID** 用于 SubHD 影片页直达（mediainfo 是否带豆瓣 ID 待 P3 核实）
- 🔶 F2.2 读取视频文件名中的片源信息（压制组、WEB-DL/BluRay、分辨率）用于版本匹配；**视频压制组**（发布名末尾 `-CMCT` 等）与字幕组分开存（D024）

### F3 字幕源
- ✅ F3.1 ASSRT：官方 API（Token，`Authorization: Bearer` 请求头）；界面注明来源「ASSRT（assrt.net）」
- ✅ F3.2 SubHD：网页接口；**不破解验证码**，触发时转人工；根域名做成配置项（默认 `subhd.tv`，备选 `subhd.me`、`subhd.one`）
- 🔶 F3.3 字幕源可插拔，统一接口，后续可加源
- ✅ F3.4 **源分工：SubHD 为主，ASSRT 补充**（D021，取代 D003 的分工部分）：先查 SubHD；SubHD 凑不满 2 份合格候选、或 SubHD 不可用（熔断 / 验证码 / 被墙）时才查 ASSRT

### F4 候选展示与选择（针对海拉鲁的痛点）
- ✅ F4.1 候选可按 **下载量 / 评分 / 上传时间** 排序
- ✅ F4.2 显示 **制作组/发布人、来源类型**（官方 / 原创翻译 / 转载精修 / 机翻 / AI 校对）、语言、格式、片源版本
  - 质量字段（下载量 / 评分 / 上传时间）拿不到时记为「无」，与 0 区分；保留每条候选在源站结果页里的原始位置（D014）
  - 字段细节（D024）：SubHD **没有评分**（`rating` 恒为「无」），「支持」点赞数另存 `like_count`；字幕组与视频压制组分开存；ASSRT `vote_score=0` 与 `release_site="个人"` 都按「无」处理；上传时间统一成带时区的时间（SubHD 为 UTC，ASSRT 无时区，推测北京时间，**不确定**）；下载量不能跨源直接比较
- 🔶 F4.3 自动打分：语言（必须含简中+外语）> 片源版本匹配 > 来源类型（官方/原创优先，机翻降权）> 下载量/评分 > 格式偏好
  - 排序只在核心层做一次，自动挑选与界面默认顺序一致；界面上的「按下载量/评分/时间排序」只改显示顺序；下载量跨源比较前先在源内归一化；字幕源优先级最多是弱权重（D021 的「SubHD 优先」体现在**查询顺序**上，不体现在打分上）；打平时退回源站原始顺序，不按标题排序（D014）
  - SubHD 来源类型样本里「其他来源」占多数，来源类型对 SubHD 是弱信号
- 🔶 F4.4 自动选出 Top 2（D022）：先取 **SubHD Top 2**；SubHD 合格候选不足 2 份时，再把 ASSRT 与 SubHD 候选**合并排序**取 Top 2；**同一个包、同一个字幕组不重复选**。手动模式下可改选

### F5 下载与解包
- ✅ F5.1 支持 ZIP / RAR / 7z 压缩包，**面向 Windows 原生运行**（D015、D020）
  - **扩展名不可信**，一律用魔数判断格式（实例：ASSRT `…4K适配HDR.zip` 实为 RAR4；下载结果也可能是裸字幕文件）
  - **zip 不交给外部工具**：标准库 zipfile 逐个成员写盘；无 UTF-8 标志的文件名由我们自己回转（UTF-8 标志 → 0x7075 Unicode Path → cp437 还原原始字节后按常用字比例在 utf-8 / gb18030 / big5 中选，平分选 gb18030，全 0 分转人工）；**必须用 `orig_filename`**（Windows 上 `\` 会被换成 `/`，而 Big5 第二字节可能是 0x5C）；解码后再统一路径分隔符
  - rar：主力 7z.exe，备用系统 tar.exe（**tar.exe 只作 rar 备用**，它解不了常规 7z）；7z：主力 7z.exe，备用 py7zr（可选，不声明为插件依赖，见 D020）
  - 工具按候选清单探测并实际运行确认；依赖状态在界面展示，缺工具时给出明确的补救提示（D020）
- ✅ F5.2 解包后按语言、格式、文件名自动挑出目标字幕；无法判断时转人工挑选
  - 保留包内目录结构（目录名里的语言、集数信息参与挑选）；内层压缩包递归解开（深度 ≤2，共用资源上限）；zip 内无 UTF-8 标志的文件名做编码回转（GBK/Big5）；解包资源上限防护（成员数、大小、路径穿越）
  - 识别**内容范围** `content_scope`：正片 / 花絮（访谈、预告）/ 导评 / 分段（cd1、cd2）；只有正片参与自动挑选；分段需整套处理或转人工
  - **文件名里的语言标记只作弱参考**，以对话正文判定为准（ASS 只取 `Dialogue` 正文，去掉 `{…}` 标签和文件头；简繁按特征字比例）；双语排列识别 3 种：同一事件上下排、按 Style 分开的两组事件、SRT 同时间轴两个条目
- ✅ F5.3 **所有输出字幕统一写成 UTF-8**（GBK/Big5 先识别再转码）；🔶 清除 SRT 中的 HTML 标签、繁转简（可选）
- ✅ F5.4 **ASS / SSA 落盘前格式校验**：去掉 BOM 和空行后第一行不是 `[Script Info]` 就补上（缺节头的 ASS 会被 Jellyfin 静默跳过，CMCT 包实例）；有可用 ffprobe 时（可配置路径，例如 Jellyfin 自带的）再跑一次探测，失败则不落盘、转人工

### F6 落盘规范
- ✅ F6.1 每部影片在**视频同目录**放 **2 份最佳双语字幕（简体中文 + 外语）**，Jellyfin 可直接识别、可在播放时选择
- ✅ F6.2 **原字幕压缩包也保存**（位置见 F6.7）
- ✅ F6.3 没有现成双语时，用「简中单语 + 外语单语」**合成**双语
- ✅ F6.4 保留扩展：仅有外文字幕时，AI 翻译成中文再合成（P7）
- 🔶 F6.5 不覆盖、不删除已有字幕；视频文件与下载目录一律不碰；新建 `Subs/HebiSubs/` 目录属于「新增」
- ✅ F6.6 **两份双语的文件命名**（D018）：`<视频名>.<序号> <语言说明>[ <来源>].zh[.default].<ext>`
  - 例：`Movie.1 中英双语 CMCT.zh.default.ass`、`Movie.2 中英双语 人人影视.zh.srt`；没有来源时 `Movie.2 中英双语.zh.ass`
  - 语言说明：`中英双语` / `中法双语`（外语换字）/ `中英双语合成`（F6.3）/ `简中`（华语片，F6.8）
  - 来源：字幕组 → 发布人；都没有就省略
  - 语言码固定 `zh`（Jellyfin → zho，能被偏好 `zho` 自动选中）；只有第 1 份带 `.default`
  - 标题清洗：去掉 `.` 和 Windows 非法字符 `\/:*?"<>|`；不得含 `default` / `forced` / `foreign` 子串（不分大小写），不得整段等于 `cc` / `hi` / `sdh` 或某个语言码；来源部分 ≤12 字；同目录重名时不覆盖（F6.5）
- ✅ F6.7 **原包存档**（D019）：影片目录下 `Subs/HebiSubs/`（Jellyfin 内置忽略 `**/subs/**`，不识别、不产生库条目）
  - 文件名：`<源>-<源站ID>-<原包名>`（原包名清洗非法字符）；裸字幕文件也照存
  - 同目录写 `HebiSubs/index.json`：记录每个存档包的来源、下载时间、sha256、对应的视频文件名和落盘字幕文件名，存档可自描述
  - `Subs/` 已存在（发布组自带的 `Subs/` 很常见）时只在里面新建 `HebiSubs/`，不碰原有内容；目录名做成配置项（默认 `Subs/HebiSubs`）
  - MP 整理 / 洗版 / 删除媒体时对该目录的处理**不确定**，P5 实测
- ✅ F6.8 **华语片也处理**，只需简中字幕，不要求双语（D017）；华语片的判定依据（TMDb 原始语言 / 地区）与落盘份数 🔶 P3 定

### F7 校验
- 🔶 F7.1 语言检测（确认真含简中 + 外语；方法见 F5.2）
- 🔶 F7.2 时长覆盖检查（字幕结束时间与视频时长）
- 🔶 F7.3 可选对轴（P5 以后）

### F8 运维与兜底
- 🔶 F8.1 每个视频一条状态记录（待处理/完成/失败/待人工），幂等可重试；记录本插件写入的字幕文件名
- 🔶 F8.2 每个字幕源独立限速 + 熔断（连续失败自动停用并通知）；限速在 HTTP 层**按请求计数**（搜索、详情、下载都算），不按「一次搜索调用」计数。默认值（D023，可配置）：
  - SubHD：请求间隔 ≥30 秒、每小时 ≤40 次；出现验证码 / 拦截页 / 403 / 429 / 503 / Cloudflare 挑战即熔断，熔断期间新任务直接走 ASSRT 补充，并标记「SubHD 未查」以便恢复后重查
  - ASSRT：按**账号实际配额**设定（本账号 5 次/分钟）→ 默认 4 次/分钟（16 秒间隔）；收到 HTTP 509（配额超限）熔断 10 分钟
  - 两个源都是全局共享的令牌桶，实时任务（自动 / 手动）优先于批量扫描
- 🔶 F8.3 Telegram 通知；人工投喂目录（浏览器手动下载的字幕放进去，插件自动接手）
- 🔶 F8.4 刷新 Jellyfin 对应条目

## 3. 非功能需求

| 项 | 要求 |
|---|---|
| 安全 | 只新增文件；开发期只写测试目录；真实库接入前备份 |
| 合规 | 遵守站点限速与条款；不破解验证码；ASSRT 注明来源 |
| 限额 | ASSRT **以账号实际配额为准**（文档写初始 20 次/分钟，本账号实测 5 次/分钟，按 token 与 IP 共享）；SubHD 低频（默认见 F8.2）。历史库批量扫描**也走 SubHD**（D021 后改），共用同一限速器，单部约 5–8 次请求，默认约 5–8 部/小时（D023） |
| 可维护 | Provider 可插拔；核心逻辑与 MP 接口层分离，便于跟随 MP 版本迁移 |
| 易用 | 依赖（7-Zip、ffprobe）自动探测、零配置可用；缺失时界面给出具体补救方法，不影响插件加载（D020） |
| 可学习 | 中文注释；文件开头写用途与用法；命名详细；显示时刻用 12 小时制标 AM/PM |
