## 研读目标
1. 模块地图：目录结构、各文件职责、依赖库
2. 一条完整链路：整理完成事件 → 识别 → 搜索 → 下载 → 解包 → 改名落盘
3. 定位三个痛点的原因：SubHD 不按下载量排序／不显示制作组／整包无法处理
4. 值得借鉴 / 应该避免的设计
5. 许可证类型

## 研读规则

> P1 所有 Claude Code 会话都按本节执行；开场白里引用「按 study-hailulu/README 研读规则」即可。

1. **只读、不复制**：只读 `_reference/`，不复制代码；引用片段不超过 5 行，并注明「文件:行号」，其余用自己的话描述（参考仓为 GPL-3.0，见 `docs/api-notes/mp-v3-plugin.md` §6）。
2. **不联网**：不访问 SubHD / ASSRT，实测留给 P2。
3. **省额度**：先用 Grep 找类/函数签名，再分段 Read，不整份通读大文件；预计要读超过约 15 个文件或明显耗额度时，先停下报告。
4. **标出处与置信度**：每个结论标出处（文件:行号，路径相对 `plugins.v3/subtitlemanualupload/`）；推断的标「推测」，没能确认的标「不确定」。
5. **产出与提交**：笔记写到 `docs/study-hailulu/0x-*.md`（编号对应任务：01=S1 模块地图、02=S2 痛点①②、03=S3 痛点③、04=S4 自动链路）；结束时写交接卡，给出 diff 摘要，用户确认后再提交（`docs: …`）。
6. **记录版本**：每份笔记头部写参考仓提交号（`git -C _reference/hailulu log -1 --format="%h %ci"`），参考仓更新后行号可能失效。
